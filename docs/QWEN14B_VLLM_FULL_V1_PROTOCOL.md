This branch is an isolated acceleration experiment.  It never reads artifacts
from the Transformers formal output as resume inputs and never writes into that
output root.

The locked environment is
`/mnt/hbnas/home/wj/conda_env/earlystop_vllm_hidden_v1`; the independent formal

## Deliberately replaced engine operations

- Dense autoregressive execution and categorical sampling are performed by
  vLLM rather than the manual Transformers loop.  The same per-problem seed and
  sampling parameters are supplied, but token equality to Transformers is not
  claimed.
- Hidden states are obtained by replaying the exact vLLM prompt + Dense token
  IDs through vLLM's `extract_hidden_states` method, then selecting
  `prompt_length + checkpoint - 1` at zero-based decoder layer 20. vLLM counts
  the embedding state as auxiliary layer 0, so the locked internal auxiliary ID
  is 21; the collector asserts this `20 + 1` mapping before engine creation.
- Greedy suffix branches are generated by vLLM from the exact prefix token IDs
  and unchanged suffix.
- vLLM 0.18.1 automatic prefix caching is the supported KV-reuse mechanism for
  the nested paragraph branch prompts. The installed high-level API has no
  public operation for forking an arbitrary saved checkpoint KV state, so the
  risk matrix does not claim a custom KV fork that vLLM cannot audit.
- Dense sampling, hidden replay, and greedy branches each run in a fresh Python
  process. This prevents CUDA, NCCL, model-registry, or engine state from one
  vLLM instance from affecting a later phase.
- `flash-attn` and `xformers` Python packages are forbidden in this environment;
  vLLM owns the locked attention runtime and stale third-party binary wheels fail
  closed before an engine is constructed.
- vLLM 0.18.1 requires Torch 2.10.0/CUDA 12.8.  Decoder attention uses vLLM's
  locked `FLASH_ATTN` backend; v0.18.1 does not expose Torch SDPA as a decoder
  backend.
- The clean environment's own `libstdc++.so.6` is preloaded so ABI resolution
  cannot depend on Python import order; no library path from the old environment
  is used.

## Fail-closed determinism gates

- Clean Git commit, exact hardware/runtime lock, and exact lock of every Python
  distribution in the isolated environment (missing, changed, and extra packages
  all fail closed).
- One visible physical GPU per worker, V1 multiprocessing and asynchronous
  scheduling disabled, fixed request order, eager execution, CUDA
  graphs/compilation disabled, and identical 0.45 GPU-memory utilization for
  every replica and gate. The selected phase profile must be recorded in every
  artifact.
- Before formal selection, compare baseline batch 1, branch-only APC batch 1,
  branch-only APC batch 2, and full APC batch 2. Batch 4 is diagnostic-only and
  may run only if batch 2 is exact and still materially unsaturated.
- Same-profile repeats must be bitwise exact for Dense token IDs, greedy branch
  token IDs/labels, and float16 hidden tensors on the same GPU and across GPU0/1.
  Baseline and batch composition/order comparisons are retained as diagnostic
  evidence but are not hard acceptance gates. Formal batch size is capped at 2
  for 40GB A100 portability.
- Bitwise exact scientific payload and hidden tensors across two independent
  runs on GPU0.
- Bitwise exact scientific payload and hidden tensors between A100 GPU0 and
  A100 GPU1.
- Exact equality of every non-engine protocol field against the existing
  Transformers gate artifact.

## Adaptive formal scheduling

Formal collection uses four fixed logical shards (`0/4` through `3/4`). Their
problem membership and in-shard request order never change. A 15-second
supervisor loop reads GPU0/GPU1 memory telemetry and places pending shards on
either A100 without touching external processes. Each active worker reserves a
40,960 MiB scheduling slot, keeps `gpu_memory_utilization=0.45`, and each GPU is
capped at two workers. GPU process ancestry separates this task's memory from
external memory, so a second replica is launched only when the remaining
external allocation still leaves another complete 40 GiB slot. Cross-GPU exact
gates justify moving a fixed logical shard between GPU0 and GPU1.

No formal shard may start unless the risk matrix and all self-reproducibility
gates pass. A crash, OOM, or a non-exact same-profile gate is evidence to
preserve; it is not retried with a changed batch, dtype, context, layer, seed,
GPU assignment, or decoding rule.
The formal supervisor requires the completed `RISK_MATRIX.json` as an input,
verifies that the requested profile is both accepted and recommended, and
records its SHA-256 in `RUN_MANIFEST.json` and `DETERMINISM_GATE.json`.
