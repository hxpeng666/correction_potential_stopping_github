# Qwen3-14B full-vLLM deterministic collection v1

This branch is an isolated acceleration experiment.  It never reads artifacts
from the Transformers formal output as resume inputs and never writes into that
output root.

The locked environment is
`/mnt/hbnas/home/wj/conda_env/earlystop_vllm_hidden_v1`; the independent formal
output is
`/mnt/hbnas/home/wj/correction_potential_stopping/results/qwen3_14b_deterministic_ood13k_vllm_full_v1`.
After the gates pass, formal workers retain the original assignment: GPU0 is
shard 0/3 and GPU1 hosts shard 1/3 plus shard 2/3. No 2080Ti is a valid formal
or determinism-gate device.

## Frozen scientific choices

- Qwen3-14B local weights and tokenizer metadata.
- DeepSeek main-v2 prompt rendering followed by the tokenizer default encoding
  path; prompt text and prompt token IDs must match the Transformers gate
  artifact exactly.  Qwen3 thinking mode remains enabled by the unmodified
  chat-template default.
- Dense base seed `20260820`, with the unchanged SHA-256 `problem_id` derivation.
- BF16 weights/KV, 13,000 token cap, temperature 0.6, top-p 0.95, top-k 20,
  sampling enabled.
- First `</think>` or full Dense content as the reasoning range; paragraph
  boundaries with no range filter.
- Zero-based layer 20 and float16 stored checkpoint tensors.
- The exact suffix `"\n</think>\n\n\\boxed{"`, greedy decoding, and a maximum of
  48 generated tokens for every checkpoint and exact-13K forced grader.
- Original data identity, split identity, gold parsing, prediction parsing,
  symbolic/numeric grader, labels, and artifact schema.

The maximum observed frozen prompt is 1,315 tokens.  Prompt + exact 13K Dense
plus six suffix tokens + greedy48 is 14,369 tokens, below the locked 16,384
context limit.

## Deliberately replaced engine operations

- Dense autoregressive execution and categorical sampling are performed by
  vLLM rather than the manual Transformers loop.  The same per-problem seed and
  sampling parameters are supplied, but token equality to Transformers is not
  claimed.
- Hidden states are obtained by replaying the exact vLLM prompt + Dense token
  IDs through vLLM's `extract_hidden_states` method, then selecting
  `prompt_length + checkpoint - 1` at zero-based decoder layer 20. vLLM counts
  the embedding state as auxiliary layer 0, so the locked internal auxiliary ID
  is 21; the collector asserts this `20 + 1` mapping before engine creation.
- Greedy suffix branches are generated by vLLM from the exact prefix token IDs
  and unchanged suffix.
- Dense sampling, hidden replay, and greedy branches each run in a fresh Python
  process. This prevents CUDA, NCCL, model-registry, or engine state from one
  vLLM instance from affecting a later phase.
- `flash-attn` and `xformers` Python packages are forbidden in this environment;
  vLLM owns the locked attention runtime and stale third-party binary wheels fail
  closed before an engine is constructed.
- vLLM 0.18.1 requires Torch 2.10.0/CUDA 12.8.  Decoder attention uses vLLM's
  locked `FLASH_ATTN` backend; v0.18.1 does not expose Torch SDPA as a decoder
  backend.
- The clean environment's own `libstdc++.so.6` is preloaded so ABI resolution
  cannot depend on Python import order; no library path from the old environment
  is used.

## Fail-closed determinism gates

- Clean Git commit, exact hardware/runtime lock, and exact lock of every Python
  distribution in the isolated environment (missing, changed, and extra packages
  all fail closed).
- One visible physical GPU per worker, V1 multiprocessing and asynchronous
  scheduling disabled, exactly one active request/sequence, fixed request order, eager
  execution, CUDA graphs/compilation disabled, prefix caching disabled, and
  identical 0.47 GPU-memory utilization for every replica and gate.
- Bitwise exact scientific payload and hidden tensors across two independent
  runs on GPU0.
- Bitwise exact scientific payload and hidden tensors between A100 GPU0 and
  A100 GPU1.
- Exact equality of every non-engine protocol field against the existing
  Transformers gate artifact.

No formal shard may start unless all three gates pass.  A crash, OOM, or any
non-exact gate is evidence to preserve; it is not retried with a changed batch,
dtype, context, layer, seed, GPU assignment, or decoding rule.
